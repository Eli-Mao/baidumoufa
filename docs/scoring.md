# 评分与约束口径

## 一、两套评分口径并存（★必须先定用哪套）

我们手上的材料里有两份规则，**分值结构完全不同**：

| 来源 | 分值结构 | 评价维度 |
|---|---|---|
| 开运联合·母版说明（`开运联合：面向空间目标持续监测...docx`） | 硬约束满足 25 / 重点目标任务效果 25 / 动态重规划 25 / 规划效率与稳定性 15 / 程序完整性与说明 10 | 为"赛题一（重点目标持续监测 + 动态重规划）"写的 |
| 开运联合·比赛规则细化（`开运联合\说明.docx`） | **计算结果 40% + 产品体验 30% + 算法效率 30%**，额外加分最多 10% | 针对"万级目标多站调度"的具体规则 |

代码当前实现的是**第二套里"计算结果"那一部分的可量化内核**（得分与覆盖），
因为它是唯一能被机器判定、且与数据直接对应的部分。
第四维（产品体验）和第五维（算法效率）分别由 `report.py` 和 `scoring.compare_algorithms` 承接。

> 待 Priime 向组委会确认后固化。见 `open_questions.md` Q3。

## 二、计分内核（`rules` 的实现口径）

### 2.1 单条任务得分

```
task_score = priority_score × duration_score(dur_s)
```

| 优先级 | `priority_score` |
|---|---|
| 高优 | 5 |
| 中优 | 3 |
| 低优 | 2 |

### 2.2 时长系数 `duration_score`

口径来自 `说明.docx`：「定轨所需要的最短观测时长 120 秒，最长观测时长 240 秒，
观测到最短时长可以获得 60% 分数，最长时长及以上可以获得 100% 分数」。

当前实现按**线性插值**：

```
dur_s < 120    -> 0.0      （非法，另判违规）
dur_s = 120    -> 0.60
dur_s = 180    -> 0.80
dur_s >= 240   -> 1.00
```

★**插值方式待确认**（线性 / 分段阶跃）→ 见 `open_questions.md` Q4。
确认后只需改 `rules.duration_score` 与 `rules.duration_score_series` 两处。

### 2.3 覆盖率类指标

| 指标 | 定义 |
|---|---|
| 目标覆盖率 | 被至少观测 1 次的卫星数 / 全部卫星数 |
| 高优先级目标覆盖率 | 被观测的高优卫星数 / 全部高优卫星数（2024 颗） |
| 加权覆盖率 | 分优先级的覆盖率（`score.json` 的 `by_priority`） |
| 站点利用率 | (Σ观测时长 + 30s × 切换次数) / (10 站 × 规划期总秒数) |

> 说明.docx 要求"尽可能完成最高分数的观测任务，**同时覆盖最多的目标**"，
> 所以是**双目标**。单目标化时用 `rules.objective(..., coverage_weight=?)` 合成，
> 权重取值要在报告里写明。

## 三、硬约束清单（`rules.plan_violations`）

| # | 约束 | 判据 | 来源 |
|---|---|---|---|
| 1 | 观测时长下限 | `dur_s ≥ 120` | 说明.docx |
| 2 | 观测时长上限 | `dur_s ≤ 240` | 说明.docx |
| 3 | 规划期内 | `0 ≤ t_start_s`，`t_end_s ≤ PLAN_DAYS × 86400` | 说明.docx |
| 4 | 必须存在观测机会 | 任务被 `windows.csv` 中某窗口完整包住 | 物理约束 |
| 5 | 同站不重叠 | 同一站任务区间互不重叠 | 说明.docx |
| 6 | 切换开销 | 同站相邻任务间隔 ≥ 30 s | 说明.docx |
| 7 | 时长自洽 | `dur_s == t_end_s - t_start_s` | 本项目附加 |

另有一条**物理自洽约束**未纳入硬约束判定（口径未确认），但已在
`scheduler._reference_greedy` 中以 `one_station_per_sat=True` 默认启用：
**同一时刻同一颗星只允许被一个站跟踪**。见 `open_questions.md` Q6。
