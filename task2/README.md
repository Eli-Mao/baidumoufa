# 赛题二：面向全球覆盖与区域重访的星座构型优化设计

洞一科技命题。程序输入卫星总数 N，自动生成太阳同步星座构型，输出每颗星在统一历元下的轨道初始参数
（高度 h、倾角 i、升交点赤经 Ω、纬度幅角 u），并按赛题评分口径自评全球覆盖（T90 / T100）
与长三角重访（Tavg / Tmax）。算法原理与设计思路见 [`docs/算法说明.md`](docs/算法说明.md)。

## 快速开始

环境：Python 3.11+，只依赖 numpy、pandas（`requirements.txt`）。以下命令都在 `task2/` 目录下运行。

```bash
python generate.py --n 28                    # 生成 28 星构型 -> out/n28/（默认搜索 600 s）
python generate.py --n 28 --exact --stk      # 另做逐步长仿真复核，并导出 STK 文件
python run_sim.py --elements out/n28/constellation.csv     # 对任意星座文件做逐步长仿真
python validate.py --const out/n28 --n 28    # 模型与输出自校验 -> out/n28/validation.json
python -m unittest discover -s tests -v      # 单元测试（约 15 s）
python sweep.py --n 28 --out out/sweep_28.csv   # Walker / 回归构型对比扫点
```

`generate.py` 参数：`--budget` 搜索时间上限（秒，默认 600），`--region` 换用官方长三角边界 GeoJSON，
`--lenient` 不按"长三角整体不足两次访问则重访 0 分"从严处理，`--seed` 随机种子。

## 输出

`out/n{N}/constellation.csv`（每颗星一行）：

| 列 | 含义 |
|---|---|
| `sat_id` | 1…N |
| `h_km` | 轨道高度，相对平均半径 6371 km |
| `inc_deg` | 倾角，由太阳同步条件按 h 求出 |
| `raan_deg` | 升交点赤经（J2000） |
| `u_deg` | 纬度幅角 u = ω + 真近点角（e = 0、ω = 0 时即平近点角） |
| `a_km` | 半长轴 = 6371 + h |
| `ecc` / `argp_deg` | 0 / 0 |

历元 2027-01-01 00:00:00 UTCG，J2000，平均根数（J2 长期项）。同目录还有 `constellation.json`
（同样内容外加元数据）、`metrics.json`（快速评估与逐步长仿真的指标）、`validation.json`，
以及 `--stk` 时的 `stk/`（见下文）。

接口按答疑 #49-2：卫星数用命令行参数 `--n` 输入；角度一律用度；所有参数都是初始历元下的值；
a = 6371 km + h。`metrics.json` 里 `Tavg_h` / `Tmax_h` / `region_visits` 是计分口径（长三角整体、不合并），
`merged` 是合并口径，`per_cell_old` 是 10-23 答疑前的逐格点口径（仅作参考）。

- 新口径下 Tavg 主要由 7 天总访问次数决定（各构型相差不到 10%），Tmax 由各轨道面过境长三角的地方时
  是否在一天里铺匀决定，差别可达几倍——10-21 版方案的 Ω 集中在少数几个时段，Tmax 达到 4.9–10.5 h。
  新方案都是轨道面在 360° 内均布的多面 Walker。
- 按同一组参考值（本次搜索与 10-21 版各项的最优值）打赛题分：28 星 88.6 vs 83.3、60 星 83.5 vs 74.7、
  100 星 88.9 vs 72.7（新 vs 10-21 版）。代价是 28 星 T90 / T100 变长 15% / 18%，60 星 T100 从 2.29 d 变成 3.43 d。
- 28 星时回归轨道构型 T90 / T100 更好（2.16 / 4.93 d），但子位置交错、Ω 均布、相位三者难以兼顾，
  Tmax 降不到 2 h 以下，综合分不如多面 Walker（见 `docs/算法说明.md` 2.4 节）。
- `metrics.json` 的 `proxy_score` 是相对本次搜索参考值 `refs` 的赛题分：28 星 92.3、60 星 83.6、100 星 89.0。
  参考值各项来自不同构型（如 60 星时 T90 最好 0.97 d、Tmax 最好 0.79 h），还有兼顾的空间，
  可加长 `--budget` 或用伐谋演化搜索策略继续挖。
- 坐标下降按时间预算停止，不同机器、不同 `--budget` 的结果会有小幅差别。

按 `all`（全部格点）口径，所有构型 7 天覆盖率都是 91.1%（纬度 82° 以上永远覆盖不到），T100 都不存在。

## 伐谋（FAMOU）

`evaluate.py` 是给伐谋用的评估器：伐谋改写构型生成策略（`designs.py` 的构型族、`optimizer.py` 的移动方式与预算分配），
每产出一个星座就用它打分，与 `generate.py` 同一套评分口径，参考值固定取自某次 `generate.py` 输出的 `metrics.json`：

```bash
python evaluate.py --elements cand.csv --refs out/n28/metrics.json --n 28
```

星座不合法（数量不对、高度越界、倾角不满足太阳同步、e ≠ 0）时输出 `-inf`。

## 评估口径

- 视场：交叉迹、沿迹半视场角都是 0.81°（答疑 #46；原文档沿迹为 0.001622°），按球面几何解出地面半宽
  530 km 时 7.49 km、700 km 时 9.90 km，视场在地面上近似为边长 2d 的方形。幅宽不变，只是每个格点
  在视场内多停留约 2–3 s。
- 全球覆盖：1°×1° 格点（格心），判据是格点到星下点轨迹的横向距离 ≤ 半幅宽。有效评价区两种口径都输出：
  `reachable` 剔除永远覆盖不到的极区（赛题文档）、`all` 全部格点（答疑 #28）；主结果按 `reachable`——
  按 `all` 口径，不侧摆的太阳同步星座永远到不了纬度约 82° 以上，任何方案都没有 T100（#41 追加提问，待答）。
- **区域重访（计分口径，答疑 #45-3 / #49-1）**：统计对象是长三角整体，不是逐格点。
  1. 某颗星只要有任一长三角 0.1° 格点落入视场，就算它在访问长三角；同一颗星相邻两次命中相隔超过 300 s
     就切成两次访问（一次过境约 1–2 分钟，同一颗星两次过境至少相隔约半圈 49 分钟，阈值取 3–40 分钟结果都一样），
     访问区间取 [首次命中, 末次命中]；
  2. 不合并（#28"重访不合并"，计分用）：所有星的访问按开始时刻排序，间隔 = [仿真开始 → 首次访问开始]、
     相邻两次 max(0, 后一次开始 − 前一次结束)、[末次访问结束 → 仿真结束]（#28 / #41 计入首尾）；
  3. 合并（参考）：各星访问区间先取并集，再按同样方式取间隔；
  4. Tavg = 全部间隔（含重叠访问产生的 0）的平均，Tmax = 最大值；整体访问次数 < 2 时重访项判 0（#49-1）。
- 区域重访（旧口径，仅作参考输出 `per_cell_old`）：逐格点统计首尾与相邻访问间隔，从未访问的格点计 168 h。
- 时间 UTC，2027-01-01 起 7 天；J2 长期项传播，J2 参考半径 6378.137 km（与 STK J2 传播器一致）。

### 已确认的答疑口径

- 不侧摆；覆盖网格 1°、重访网格 0.1°；允许各星不同高度（#41）。
- STK 11.6、J2 传播器、UTCG、平均根数；覆盖合并、重访不合并；重访计入首尾（#18、#23、#28、#41）。
- u = ω + f；单次有效访问没有最短持续时长；允许同一轨道面放多颗星；重访间隔的统计对象是长三角整体（#45）。
- 载荷沿迹半视场角改为 0.81°，与交叉迹相同（#46）。
- "至少两次有效访问"按整个长三角算；N 用命令行参数输入，角度用度，参数统一在初始历元表示，a = 6371 km + h（#49）。

### 已知假设 / 待确认

1. **全球有效区是否剔除极区**（#41 追加提问，10-23 仍未答复）：不侧摆时 |纬度| > 约 82° 的格点永远覆盖不到。
   若不剔除，任何方案都没有 T100，全球项最多 28 分；两种口径都已输出（`reachable` / `all`）。
2. **长三角边界**：赛题只给了 STK AreaTarget 的生成脚本（需联网下载 geoBoundaries），这里内置的是
   按省界轮廓简化的多边形（3957 个 0.1° 格点，比四省实际面积多出近海部分）。拿到官方边界后用 `--region` 替换。
3. **整体口径的细节**：答疑只说"统计对象是长三角整体"，没有说同一颗星一次过境怎么切分、重叠访问怎么计。
   这里按上文 1–4 处理，合并 / 不合并两种结果都输出；不合并时重叠访问产生 0 间隔、拉低 Tavg。

## STK 文件（`--stk`）

本机没有 STK，下列文件未在 STK 中实测，导入后请先核对：

1. `stk/ephem/SAT_xxx.e`：每颗星 7 天、30 s 步长的 J2000 星历（与评估同一 J2 长期项模型），
   卫星传播器选 StkExternal 指向该文件即可复现我们评估用的轨迹；
2. `stk/build_scenario.txt`：Connect 命令，按赛题条件建场景、用 J2Perturbation 传播器按经典根数建星、
   每颗星挂矩形传感器 `Rectangular 0.81 0.81`（沿迹、交叉迹半角都是 0.81°，答疑 #46）。
   选矩形而不是 `SimpleCone 0.81`：两者幅宽相同，矩形与我们仿真用的方形视场判据一致。

覆盖分析在 STK 界面里设置：Coverage Definition 用 Global（Lat/Lon 1°）与长三角 AreaTarget（0.1°），
Assets 选全部传感器；Figure of Merit 用 Coverage Time（T90/T100 取累计覆盖率曲线）；
长三角整体重访按"各星对 AreaTarget 的 Access 区间"统计（与 `fasteval.region_revisit` 同一算法），
而不是逐格点的 Revisit Time FOM。分析步长全球 10 s、区域 1 s。
