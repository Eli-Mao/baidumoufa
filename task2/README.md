# 赛题二：面向全球覆盖与区域重访的星座构型优化设计

洞一科技命题。程序输入卫星总数 N，自动生成太阳同步星座构型，输出每颗星在统一历元下的轨道初始参数
（高度 h、倾角 i、升交点赤经 Ω、纬度幅角 u），并按赛题评分口径自评全球覆盖（T90 / T100）
与长三角重访（Tavg / Tmax）。算法原理与设计思路见 [`docs/算法说明.md`](docs/算法说明.md)。

## 快速开始

环境：Python 3.11+，只依赖 numpy、pandas（`requirements.txt`）。以下命令都在 `task2/` 目录下运行。

```bash
python generate.py --n 28                    # 生成 28 星构型 -> out/n28/（默认搜索 600 s）
python generate.py --n 28 --exact --stk      # 另做逐步长仿真复核，并导出 STK 文件
python run_sim.py --elements out/n28/constellation.csv     # 对任意星座文件做逐步长仿真
python validate.py --const out/n28 --n 28    # 模型与输出自校验 -> out/n28/validation.json
python -m unittest discover -s tests -v      # 单元测试（约 10 s）
python sweep.py --n 28 --out out/sweep_28.csv   # Walker / 回归构型对比扫点
```

`generate.py` 参数：`--budget` 搜索时间上限（秒，默认 600），`--region` 换用官方长三角边界 GeoJSON，
`--lenient` 不按"格点不足两次访问则重访 0 分"从严处理，`--seed` 随机种子。

## 输出

`out/n{N}/constellation.csv`（每颗星一行）：

| 列 | 含义 |
|---|---|
| `sat_id` | 1…N |
| `h_km` | 轨道高度，相对平均半径 6371 km |
| `inc_deg` | 倾角，由太阳同步条件按 h 求出 |
| `raan_deg` | 升交点赤经（J2000） |
| `u_deg` | 纬度幅角 u = ω + 真近点角（e = 0、ω = 0 时即平近点角） |
| `a_km` | 半长轴 = 6371 + h |
| `ecc` / `argp_deg` | 0 / 0 |

历元 2027-01-01 00:00:00 UTCG，J2000，平均根数（J2 长期项）。同目录还有 `constellation.json`
（同样内容外加元数据）、`metrics.json`（快速评估与逐步长仿真的指标）、`validation.json`，
以及 `--stk` 时的 `stk/`（见下文）。正式提交的接口格式待主办方答复（答疑 #49），届时只需改 `generate.output_table`。

## 结果

默认参数（搜索 600 s）生成，指标为逐步长仿真（全球 10 s、区域 1 s）复核值，与快速评估一致到 0.01 h：

| N | 选出的构型 | T90 | T100 | Tavg | Tmax | 每格点最少访问 |
|---|---|---|---|---|---|---|
| 28 | 73 圈/5 天回归轨道（694.6 km），均匀分散排布，整体旋转 350.5° | **2.161 d** | **4.933 d** | **33.99 h** | **119.9 h** | 2 |
| 60 | Walker 60 面 F=15（700 km），整体旋转 14° | 1.167 d | 2.292 d | 19.82 h | 57.08 h | 5 |
| 100 | Walker 4 面 F=1（700 km），整体旋转 156° | 0.735 d | 1.962 d | 12.80 h | 29.41 h | 10 |

对照（未旋转、未做坐标下降的普通 Walker）：

| N | 构型 | T90 | T100 | Tavg | Tmax | 每格点最少访问 |
|---|---|---|---|---|---|---|
| 28 | 题目基准 7 面 × 4 星（530 km） | 6.80 d | 未达到（7 天覆盖 90.5%） | 46.05 h | 168.0 h | 0（1201 个格点不足两次） |
| 28 | Walker 14 面 × 2 星 F=3（700 km） | 2.492 d | 5.873 d | 38.31 h | 141.6 h | 2 |
| 60 | Walker 60 面 F=15（700 km） | 1.171 d | 2.292 d | 20.12 h | 57.44 h | 5 |
| 100 | Walker 4 面 F=1（700 km） | 0.736 d | 1.962 d | 12.82 h | 30.00 h | 10 |

- 28 星：回归轨道构型在四项上都优于最好的普通 Walker（T90 −13%、T100 −16%、Tavg −11%、Tmax −15%）。
- 60 / 100 星：初选里普通 Walker 已最好，整体旋转与坐标下降只带来 1–2% 的改进。
  各单项的最优值（参考值）来自不同构型，如 60 星时 T90 最好 0.97 d、Tmax 最好 38.8 h，
  说明还有兼顾的空间，可加长 `--budget` 或用伐谋演化搜索策略继续挖。
- 坐标下降按时间预算停止，不同机器、不同 `--budget` 的结果会有小幅差别（28 星 300 s 与 600 s 两次的赛题分差 0.2）。

按 `all`（全部格点）口径，所有构型 7 天覆盖率都是 91.1%（纬度 82° 以上永远覆盖不到），T100 都不存在。

## 伐谋（FAMOU）

`evaluate.py` 是给伐谋用的评估器：伐谋改写构型生成策略（`designs.py` 的构型族、`optimizer.py` 的移动方式与预算分配），
每产出一个星座就用它打分，与 `generate.py` 同一套评分口径，参考值固定取自某次 `generate.py` 输出的 `metrics.json`：

```bash
python evaluate.py --elements cand.csv --refs out/n28/metrics.json --n 28
```

星座不合法（数量不对、高度越界、倾角不满足太阳同步、e ≠ 0）时输出 `-inf`。

## 评估口径

- 覆盖判据：格点到星下点轨迹的横向距离 ≤ 地面半幅宽（由交叉迹半视场角 0.81° 按球面几何解出，
  530 km 时 7.49 km、700 km 时 9.90 km）；沿迹视场只有 30 m，按理想连续推扫处理。
- 全球覆盖：1°×1° 格点（格心）。有效评价区两种口径都输出：`reachable` 剔除永远覆盖不到的极区
  （赛题文档）、`all` 全部格点（答疑 #28）；主结果按 `reachable`——按 `all` 口径，不侧摆的太阳同步星座
  永远到不了纬度约 82° 以上，任何方案都没有 T100（已在答疑表追问）。
- 区域重访：长三角 0.1°×0.1° 格点。每个格点的间隔 = [仿真开始 → 首次访问]、相邻访问之差、[末次访问 → 仿真结束]，
  从未访问的格点计一个 168 h 的间隔；全部格点的间隔合并后取平均（Tavg）与最大（Tmax）（答疑 #28 / #41、赛题文档公式）。
- 赛题规定"重点区域不足两次有效访问可直接判 0 分"，默认按格点从严处理（#49 已问是按格点还是按整个区域）。
- 时间 UTC，2027-01-01 起 7 天；J2 长期项传播，J2 参考半径 6378.137 km（与 STK J2 传播器一致）。

### 已确认的答疑口径

不侧摆；覆盖网格 1°、重访网格 0.1°；允许各星不同高度（#41）。STK 11.6、J2 传播器、UTCG、平均根数；
视场在 530 km 高度下为 15 km × 30 m 的矩形；覆盖合并、重访不合并；重访计入首尾（#18、#23、#28）。

### 已知假设 / 待确认

1. **长三角边界**：赛题只给了 STK AreaTarget 的生成脚本（需联网下载 geoBoundaries），这里内置的是
   按省界轮廓简化的多边形（3957 个 0.1° 格点，比四省实际面积多出近海部分）。拿到官方边界后用 `--region` 替换。
2. **不足两次访问**、**全球有效区**、**输出接口**：见答疑 #49 与 #28 追问。
3. **从未访问的格点**怎么计入重访（#45 第 3 问）：这里按一个整段间隔计。
4. **极窄沿迹视场在 STK 里可能漏判访问**（#46）：我们的判据是理想推扫；如果主办方的 STK 结果出现大面积无访问，
   差异来自 STK 的采样方式而不是构型。
5. **轨道高度换算**：按 a = 6371 + h（赛题"地球半径按平均半径考虑"）；若主办方按 WGS84 赤道半径换算，
   全部卫星的周期会一起变长约 0.16%，回归构型会缓慢漂移，覆盖与重访数值需重算（#49 已问）。

## STK 文件（`--stk`）

本机没有 STK，下列文件未在 STK 中实测，导入后请先核对：

1. `stk/ephem/SAT_xxx.e`：每颗星 7 天、30 s 步长的 J2000 星历（与评估同一 J2 长期项模型），
   卫星传播器选 StkExternal 指向该文件即可复现我们评估用的轨迹；
2. `stk/build_scenario.txt`：Connect 命令，按赛题条件建场景、用 J2Perturbation 传播器按经典根数建星、
   每颗星挂矩形传感器（交叉迹半角 0.81°、沿迹半角 0.001622°；导入后确认 0.81° 那一侧对着交叉迹方向）。

覆盖分析在 STK 界面里设置：Coverage Definition 用 Global（Lat/Lon 1°）与长三角 AreaTarget（0.1°），
Assets 选全部传感器；Figure of Merit 用 Coverage Time（T90/T100 取累计覆盖率曲线）与 Revisit Time；
分析步长全球 10 s、区域 1 s。
