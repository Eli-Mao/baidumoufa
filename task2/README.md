## 快速开始

环境：Python 3.11+，依赖 numpy、pandas、scipy、pyerfa（`requirements.txt`）。
原生工程验证另需 Windows、STK 11.6 Engine 和可用的 Coverage 许可。以下命令都在 `task2/` 目录下运行。

```bash
python generate.py --n 28 --out out/new_design_stk --region data/official_region/yangtze_river_delta_boundary.geojson  # 新 STK 约定，搜索仍用区域格点代理
python generate.py --n 28 --out out/new_design_stk --region data/official_region/yangtze_river_delta_boundary.geojson --exact --stk  # 另做代理复核及正式边界导出
python run_sim.py --elements out/n28/constellation.csv     # 复现历史网格代理诊断
python engineering_run.py                    # 固定输入的完整 Python + STK 验证，写入新时间戳目录
python validate.py --const out/n28 --n 28    # 模型与输出自校验 -> out/n28/validation.json
python -m unittest discover -s tests -v      # 单元测试及独立 STK 数据回归
python sweep.py --n 28 --out out/sweep_28.csv   # Walker / 回归构型对比扫点
```

`generate.py` 参数：`--budget` 搜索时间上限（秒，默认 600），`--region` 换用官方长三角边界 GeoJSON，
`--lenient` 不按"长三角整体不足两次访问则重访 0 分"从严处理，`--seed` 随机种子。

`--rate-model stk` 是新构型默认值，`--rate-model first_order` 用于复现历史设计。输出记录模型类型；
检查与评估会识别输入约定，并拒绝用不同约定的评分参考值混算。
复核同一输入时可显式使用 `python engineering_run.py --reuse-stk out/stk_validation_eop2026 --out out/engineering_recheck`；
只有完整物理输入及证据哈希匹配才允许复用全量原生基线，Python、短时窗口精化和新设计太阳同步检查仍重新执行。

## 评估口径

- 视场：交叉迹、沿迹半视场角都是 0.81°（答疑 #46；原文档沿迹为 0.001622°），按球面几何解出地面半宽
  530 km 时 7.49 km、700 km 时 9.90 km，视场在地面上近似为边长 2d 的方形。幅宽不变，只是每个格点
  在视场内多停留约 2–3 s。
- 全球覆盖：1°×1° 格点（格心），以格点数量统计；按设计倾角动态剔除永久不可达高纬区域（`G41`、`E55`），主结果采用 `reachable`。
  `all` 继续作为诊断输出；“极区是否剔除”已经明确，不再是待答问题。实际格心原点和边界恰落在格点时的数值容差仍须在 STK 中核对。
- **当前区域规则：**`E41` 明确长三角整体、不做网格划分；`E45`、`E49` 确认整体统计和至少两次访问要求。
  应以正式边界与传感器几何得到区域访问区间，不能把任一 0.1° 格点命中作为正式定义。
- **以下是历史代理实现，仅用于旧结果复现：**
  1. 某颗星只要有任一长三角 0.1° 格点落入视场，就算它在访问长三角；同一颗星相邻两次命中相隔超过 300 s
     就切成两次访问（一次过境约 1–2 分钟，同一颗星两次过境至少相隔约半圈 49 分钟，阈值取 3–40 分钟结果都一样），
     访问区间取 [首次命中, 末次命中]；
  2. 不合并（项目对 #28 的解释）：所有星的访问按开始时刻排序，间隔 = [仿真开始 → 首次访问开始]、
     相邻两次 max(0, 后一次开始 − 前一次结束)、[末次访问结束 → 仿真结束]（#28 / #41 计入首尾）；
  3. 合并（参考）：各星访问区间先取并集，再按同样方式取间隔；
  4. Tavg = 全部间隔（含重叠访问产生的 0）的平均，Tmax = 最大值；整体访问次数 < 2 时重访项判 0（#49-1）。
- 区域重访（旧口径，仅作参考输出 `per_cell_old`）：逐格点统计首尾与相邻访问间隔，从未访问的格点计 168 h。
- 时间 UTC，2027-01-01 起 7 天；J2 长期项传播，本地 J2 参考半径 6378.137 km；STK 常数与平均根数定义须实机核对。

### 已确认的答疑口径

- 不侧摆；覆盖网格 1°、重访针对整体且不划网格；允许各星不同高度（工作表1 `E41`）。
- 根据设计倾角动态剔除无法到达的极高纬区域（工作表1 `G41`、`E55`）。
- STK 11.6、J2 传播器、UTCG、平均根数；覆盖合并、重访不合并；重访计入首尾（#18、#23、#28、#41）。
- u = ω + f；单次有效访问没有最短持续时长；允许同一轨道面放多颗星；重访间隔的统计对象是长三角整体（#45）。
- 载荷沿迹半视场角改为 0.81°，与交叉迹相同（#46）。
- "至少两次有效访问"按整个长三角算；N 用命令行参数输入，角度用度，参数统一在初始历元表示，a = 6371 km + h（#49）。

## STK 工程验证（2026-11-10）

`engineering_run.py` 是正式工程验证入口。默认重新计算 Python 和原生 STK，使用
`data/validation_profile.json` 中冻结的 EOP、正式区域边界、历元和采样设置。结果写入新的时间戳目录；
输出目录不能覆盖已有证据。运行清单记录输入/源码哈希、依赖版本、实际命令及退出状态。

本轮 68 项测试通过，另有 12 组新设计的实机太阳同步检查。28 星七天共有 282268 条轨道对照样本，
最大位置差约 0.14 毫米。全局 59040 个有效点在短时访问精化后覆盖状态和访问次数全部对应，
长三角 169 条逐星窗口的最大端点差约 0.0084 秒。有限步长收敛是所述输入下的工程证据，
不能证明任意构型的任意短访问都不会遗漏。详细结果见 [轨道与 STK 工程验证](docs/轨道与STK工程验证.md)。

全球采用明确的 1° 格心点表按点计数；区域采用 WGS84 椭球上的正式连续边界和矩形视场相交。
同星合并各区域组成部分重叠或相接的窗口，保留正长度间断；跨星不合并，计入首尾间隔。
`out/stk_validation_eop2026/` 与 [2026-11-05 实机记录](docs/STK实机验证记录.md) 保留历史全量原生基线。
