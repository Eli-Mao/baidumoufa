### Role

你是航天任务设计与组合优化方向的算法工程师，负责改进一个"按卫星总数 N 自动设计太阳同步星座"的程序。

### Task

改进 init.py 中 EVOLVE-BLOCK 内的设计策略：在给定时间预算内，为 N 颗星给出太阳同步圆轨道星座，
使全球覆盖更快、长江三角洲区域重访更频繁。评估器对多个 N（28、37、60、100）分别运行程序，
按赛题评分公式打分后取平均，分数越高越好。

### Requirements

1. 调用契约不变：`python init.py --n N --budget 秒 --out 星座.csv`。入口 `design(N, jd0, budget_s)`
   返回 N 行、含 alt_km, inc_deg, raan_deg, u_deg 的 DataFrame；EVOLVE-BLOCK 之外的代码不要改。
2. 硬约束（违反任一条即判 0 分）：
   - 恰好 N 颗星，程序对任意 N 都要能给出结果，不能只适配某几个 N；
   - 轨道高度 500 ≤ h ≤ 700 km，可以各星不同；
   - 倾角必须等于 `sso.sso_inclination(h)`（太阳同步条件），偏心率 0；
   - 运行时间不超过 预算 × 1.25 + 60 秒（默认预算 120 秒），超时、报错、未写出文件都判 0 分；
   - 只写 --out 指定的文件，不得读写或修改评估器、refs.json 和 task2 下的其他模块。
3. 只能用 numpy、pandas 与 task2 的固定模块：designs（构型族与轨迹平移换算）、fasteval（快速评估）、
   score（评分公式）、sso（太阳同步与 J2 速率）、constellation（历元）。
4. 不要读取 out/ 下已有的星座结果，也不要硬编码某个 N 的答案。

### Evaluation

单个 N 的赛题分（满分约 100，以固定参考值为"最优值"，优于参考值可超过 100）：
    全球覆盖 40 分 = 28 × T90*/T90 + 12 × T100*/T100
    区域重访 60 分 = 42 × Tavg*/Tavg + 18 × Tmax*/Tmax
- T90 / T100：7 天仿真内全球（1° 格点，剔除永远覆盖不到的极区）累计覆盖率达到 90% / 100% 的时刻；
  未达 90% 时覆盖项 0 分，达到 90% 但未全覆盖时 T100 项 0 分。
- Tavg / Tmax：长三角整体的重访间隔均值 / 最大值（任一颗星的视场扫到区域内任一格点即算一次访问，
  不合并相邻访问，计入仿真首尾两段间隔）；长三角整体 7 天内不足两次访问时重访项 0 分。
- 卫星视场：交叉迹半视场角 0.81°（530 km 时地面幅宽约 15 km），不侧摆。
combined_score = 各 N 赛题分的平均。

### Data description

无外部数据文件。历元 2027-01-01 00:00:00 UTCG，J2000 平均根数，J2 长期项传播；
h 相对平均半径 6371 km（a = 6371 + h），u 为纬度幅角。长三角边界由 region 模块内置。

### Reference feasible solution

当前 init.py（Walker 与回归轨道构型初选 → 整体旋转升交点赤经 → 逐星坐标下降）在默认任务上的成绩：
N=28 91.9、N=37 85.3、N=60 79.3、N=100 80.0，平均 84.1。
不做任何搜索的普通 Walker（P ≈ √N 面）平均 56.8。

### Optimization strategies (optional)

- 太阳同步轨道过境长三角的地方时由升交点赤经决定：各星升交点赤经在一天里铺得越匀、过境时刻越错开，
  Tmax 越小；Tavg 主要取决于 7 天内的总访问次数。
- 回归轨道（D 天回归 Q 圈）能在 D 天内铺满全球；轨迹平移整数个格距 360°/Q 不改变覆盖集合，只改时序。
- 可以尝试：不同高度混合、非均匀格子分配、Walker 与回归构型混合、模拟退火或成对交换等新的搜索算子，
  以及初选 / 旋转 / 坐标下降之间的时间分配。N 大时单次全量评估约 0.5 秒，注意预算。
