# 星座构型生成算法说明

赛题：面向全球覆盖与区域重访的星座构型优化设计（洞一科技）。程序输入卫星总数 N，输出每颗星在
历元 2027-01-01 00:00:00 UTCG、J2000 下的轨道初始参数（高度 h、倾角 i、升交点赤经 Ω、纬度幅角 u）。

## 1. 问题与评分

| 项 | 指标 | 权重 |
|---|---|---|
| 全球覆盖 40 分 | T90：全球累计覆盖率首次达到 90% 的时间 | 28 |
| | T100：有效评价区全部覆盖的时间 | 12 |
| 区域重访 60 分 | Tavg：长三角全部格点有效重访间隔的平均 | 42 |
| | Tmax：全部间隔中的最大值 | 18 |

每项按"当届最优值 / 本方案值"折算。统一条件：太阳同步圆轨道、高度 500–700 km、J2 传播、
线阵推扫相机（530 km 时幅宽 15 km，幅宽与高度成正比）、对地定向不侧摆、仿真 7 天。

## 2. 基本原理

### 2.1 太阳同步条件决定倾角

J2 一阶长期项下节点进动率 Ω̇ = −(3/2)·J2·n·(Re/a)²·cos i。令 Ω̇ 等于太阳平黄经的年变化率
（360°/365.2422 天），由高度 h 唯一确定倾角 i(h)（`sso.sso_inclination`）。
a = 6371 km + h（赛题按平均半径），J2 项的参考半径取 6378.137 km（与 STK J2 传播器一致）。
因此每颗星真正的设计变量只有 (h, Ω, u)。

### 2.2 所有星的地面轨迹是同一条曲线的平移

同一高度的太阳同步圆轨道，倾角、Ω̇、u̇ 都相同。两颗星的 (Ω, u) 相差 (ΔΩ, Δu) 时，后一颗星的
地面轨迹等于前一颗星的轨迹**整体东移 c = ΔΩ + (ω_E − Ω̇)·δt、时间提前 δt = Δu / u̇**。
于是星座设计等价于给每颗星选一个"轨迹平移量 c_j"和"时间提前量 δt_j"（`designs.from_track_offsets`）。

- 全球覆盖只取决于各条轨迹在赤道附近的穿越点是否把经度铺满；
- 区域重访取决于哪些轨迹、在什么时刻扫过长三角。

### 2.3 回归轨道：覆盖与重访都有上界

若高度使卫星 D 天恰好绕 Q 圈（太阳同步时 ω_E − Ω̇ = 2π/天，条件为 u̇ = 2π·Q/(D·86400 s)），
地面轨迹每 D 天重复一次，单星在赤道上的升交点构成间距 360°/Q 的格子。让 N 颗星的轨迹在一个格距内
等分错开 360°/(QN)：

- 只要 360°/(QN) 不超过幅宽，D 天内全球就会被铺满（T100 ≈ D 天）；
- 长三角每个格点每个周期都会被扫到，重访间隔有上界（≈ D 天）；
- 把一颗星的轨迹再平移整数个格距 360°/Q，D 天内的覆盖集合不变，只改变它扫过各处的先后——
  这是一个"不损失覆盖、只调时序"的自由度，用来压低 T90 与 Tmax。

赛题高度范围内可用的回归周期（`designs.rgt_options`）如 73 圈/5 天（≈695 km）、89 圈/6 天（≈620 km）等。

### 2.4 整体旋转只影响区域重访

把所有星的 Ω 同时加一个角度，全部地面轨迹整体东移，全球覆盖指标不变；但对回归轨道，轨迹是固定的几条，
旋转决定了有几条轨迹、在什么时刻扫过长三角。28 星、73/5 回归构型的 Tavg 随旋转角在 31.6–45.1 h 之间变化。
这一步相当于把"哪几条回归轨迹落在长三角上"作为单独的设计变量来优化。

## 3. 评估：解析穿越法

逐步长仿真（10 s / 1 s 步长扫描 64800 个全球格点和 3957 个区域格点）对 28 星需要约 2.3 s，
不适合大规模搜索。`fasteval.py` 改用解析法：

- 纬度 φ(t) = asin(sin i · sin u(t))，u 随时间线性增长，穿过某一纬度行的 u 只有升段、降段两个值，
  对应时刻是等差数列；穿越点经度 λ = Ω + Ω̇t − GMST(t) + atan2(cos i sin u, cos u) 也是解析的；
- 在穿越点附近把地面轨迹看成直线：该行上横向距离 ≤ 地面半幅宽 d 的点，经度偏差满足
  |Δλ| ≤ d·|v| / (R·cos φ·|v_N|)（v 为地固系地面速度，v_N 为北向分量）；
- 每次穿越只覆盖该行上的一两个格点，直接写入"首次覆盖时刻"（全球）或"访问时刻列表"（区域）。

单次评估 28 星约 0.15 s，改一颗星只需重算这一颗（约 6 ms）。与逐步长仿真（`exactsim.py`）
对比，T90/T100 与区域 Tavg/Tmax 一致到 0.01 天 / 0.01 小时（`validate.py` 第 7 项）。

## 4. 优化算法（`optimizer.py`）

目标函数直接用赛题评分公式（`score.py`）：

  J = 28·T90*/T90 + 12·T100*/T100 + 42·Tavg*/Tavg + 18·Tmax*/Tmax

拿不到别队的最优值，就把**本次搜索中所有评估过的构型里各指标的最优值**当作 *（相当于假设对手都能
做到我们在每一项上能做到的最好），并按赛题规则处理特殊情况：未达 90% 覆盖则全球项为 0，
未全覆盖则 T100 项为 0，有格点不足两次有效访问则重访项为 0。搜索时另加少量平滑辅助项
（覆盖时刻 99% 分位、平均首次覆盖时刻、重访间隔 99% 分位），只用来提供改进方向。

四个阶段：

1. **构型初选**：Walker（多种面数 P、相位因子 F，N 不整除时前几个面多放一颗）；
   每个回归周期下的回归交错构型（N 颗星等分一个格距，按"成簇 / 均匀分散 / 黄金分割跳格"三种方式分配格子），
   以及把得分最高的 3 个 Walker 结构放到各回归高度上。共约 150–165 个构型。
2. **整体旋转**：对得分最高的 6 个构型，在 0–360° 内按 3° 粗扫、0.25° 细扫整体旋转角，
   只算区域重访（全球覆盖不变），取重访得分最高的角度。
3. **坐标下降**：对前 2 名逐颗卫星做一维穷举——回归构型试遍 Q−1 个整格平移和一圈内 36 个时间提前量，
   其他构型对平移量与时间提前量各做"72 点粗网格 → 9 点细网格 ×2"的三级搜索；
   只接受使 J 上升的移动，直到一整轮没有改进或用完时间预算。
4. 取 J 最高的构型，换算成 (h, i, Ω, u) 输出。

随机性只有坐标下降的卫星顺序（固定种子）；但坐标下降按时间预算停止，不同机器、不同预算下
跑的轮数不同，结果会有小幅差别。默认时间预算 600 s，可用 `--budget` 调整。

### 4.0 结果示例

| N | 选出的构型 | T90 | T100 | Tavg | Tmax |
|---|---|---|---|---|---|
| 28 | 73 圈/5 天回归轨道（694.6 km），均匀分散排布，整体旋转 350.5° | 2.161 d | 4.933 d | 33.99 h | 119.9 h |
| 28（对照） | Walker 14 面 × 2 星 F=3（700 km） | 2.492 d | 5.873 d | 38.31 h | 141.6 h |
| 60 | Walker 60 面 F=15（700 km），整体旋转 14° | 1.167 d | 2.292 d | 19.82 h | 57.08 h |
| 100 | Walker 4 面 F=1（700 km），整体旋转 156° | 0.735 d | 1.962 d | 12.80 h | 29.41 h |

28 星时回归轨道构型四项全面优于最好的普通 Walker；60、100 星时初选的 Walker 已最好，
旋转与坐标下降改进 1–2%。

### 4.1 全球覆盖与区域重访的权衡

两者的矛盾在于：回归轨道的轨迹固定，可以让更多条轨迹落在长三角上（Tavg、Tmax 好），
但回归周期越短，全球铺满所需的轨迹数越多（T90、T100 差）；非回归轨道（如高度取上限的 Walker）
轨迹不断漂移，全球铺得快，但每个长三角格点被扫到的时刻是随机的，Tmax 很差。
算法不预设偏向哪一边，而是用赛题权重直接比较：回归周期、构型族由初选决定，
"哪几条轨迹落在长三角"由整体旋转决定，各星时序由坐标下降决定。

### 4.2 轨道面与相位

输出不限定 Walker 形式：每颗星的 Ω、u 由轨迹平移量与时间提前量换算得到，
因此一般每颗星都在各自的轨道面上（N 个轨道面）。对回归交错构型，相邻星的升交点赤经相差约
360°/(QN) 加整数个格距，相位由时间提前量决定；若初选或坐标下降保留了 Walker 结构，
则输出也保留其轨道面分组。

### 4.3 与伐谋的结合

程序里的"智能决策"体现在构型族的选择、整体旋转与逐星坐标下降都由评分公式驱动、自动完成。
伐谋用于在此基础上演化搜索策略本身：`evaluate.py` 把任意候选星座按同一套口径折算成赛题分
（参考值固定，最后一行输出裸分数），伐谋改写 `designs.py` 的构型族与 `optimizer.py` 的移动方式、
预算分配，以评估分为适应度迭代。

## 5. 与工程仿真的对应关系

- 输出为平均根数（J2000，历元 2027-01-01 00:00:00 UTCG），e = 0、ω = 0，u 为纬度幅角；
  a = 6371 km + h。STK 中用 J2Perturbation 传播器、按经典根数（a、e、i、ω、Ω、M = u）建星即可复现。
- `stk_export.py` 另外按同一模型导出每颗星 7 天 30 s 步长的 J2000 星历（.e），
  以及建场景、加矩形传感器（交叉迹半角 0.81°、沿迹半角 0.001622°）的 Connect 命令。
- 评估用的覆盖判据是"格点到星下点轨迹的横向距离 ≤ 地面半幅宽"（理想连续推扫）。
  STK 用极窄沿迹视场做 Access 时可能漏判（答疑 #46 待答），复核时如出现大面积"无访问"，
  先检查 STK 覆盖分析的步长与传感器朝向。
