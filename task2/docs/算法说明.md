# 星座构型生成算法说明

赛题：面向全球覆盖与区域重访的星座构型优化设计（洞一科技）。程序输入卫星总数 N，输出每颗星在
历元 2027-01-01 00:00:00 UTCG、J2000 下的轨道初始参数（高度 h、倾角 i、升交点赤经 Ω、纬度幅角 u）。

## 1. 问题与评分

| 项 | 指标 | 权重 |
|---|---|---|
| 全球覆盖 40 分 | T90：全球累计覆盖率首次达到 90% 的时间 | 28 |
| | T100：有效评价区全部覆盖的时间 | 12 |
| 区域重访 60 分 | Tavg：长三角**整体**重访间隔的平均 | 42 |
| | Tmax：全部间隔中的最大值 | 18 |

每项按"当届最优值 / 本方案值"折算。统一条件：太阳同步圆轨道、高度 500–700 km、J2 传播、
线阵推扫相机（530 km 时幅宽 15 km，幅宽与高度成正比）、对地定向不侧摆、仿真 7 天。

10-23 答疑改变了重访口径：统计对象是长三角整体而不是逐个 0.1° 格点（#45-3），"至少两次有效访问"
也按整个长三角算（#49-1）；载荷沿迹半视场角改为 0.81°，与交叉迹相同（#46）。已有口径不变：
覆盖合并、重访不合并、计入首尾间隔（#28 / #41），u = ω + f，无最短访问时长，允许同面多星（#45）。

## 2. 基本原理

### 2.1 太阳同步条件决定倾角

J2 一阶长期项下节点进动率 Ω̇ = −(3/2)·J2·n·(Re/a)²·cos i。令 Ω̇ 等于太阳平黄经的年变化率
（360°/365.2422 天），由高度 h 唯一确定倾角 i(h)（`sso.sso_inclination`）。
a = 6371 km + h（赛题按平均半径，#49-2），J2 项的参考半径取 6378.137 km（与 STK J2 传播器一致）。
因此每颗星真正的设计变量只有 (h, Ω, u)。

### 2.2 所有星的地面轨迹是同一条曲线的平移

同一高度的太阳同步圆轨道，倾角、Ω̇、u̇ 都相同。两颗星的 (Ω, u) 相差 (ΔΩ, Δu) 时，后一颗星的
地面轨迹等于前一颗星的轨迹**整体东移 c = ΔΩ + (ω_E − Ω̇)·δt、时间提前 δt = Δu / u̇**。
于是星座设计等价于给每颗星选一个"轨迹平移量 c_j"和"时间提前量 δt_j"（`designs.from_track_offsets`）。

- 全球覆盖只取决于各条轨迹在赤道附近的穿越点是否把经度铺满；
- 区域重访取决于哪些轨迹、在一天里什么时刻扫过长三角。

### 2.3 长三角整体重访由"过境地方时"决定

太阳同步轨道每个轨道面经过某一纬度的地方时是固定的（升段、降段各一个），长三角东西跨约 9°，
地方时只差 ±18 分钟。所以每个轨道面只可能在一天里的两个固定时段扫过长三角，当天到底扫没扫到，
取决于那一圈地面轨迹的经度。由此：

- **Tavg 主要看 7 天的总访问次数**：间隔之和 ≈ 168 h − 访问总时长，Tavg ≈ (168 h − 访问总时长) / (访问次数 + 1)。
  每颗星平均每天扫到长三角约 0.65–0.75 次（28 星 7 天约 125–135 次）；回归轨道可以把轨迹固定在长三角上，
  多出 10% 左右的访问。
- **Tmax 看访问在一天里是否均匀**：各轨道面的升交点地方时（即 Ω）要在 24 h 内铺开，并且每个时段在每一天
  都要有星扫到——后者由各星相位（哪颗星哪天扫到）决定。

例：10-21 版 28 星方案（73 圈 / 5 天回归轨道，按逐格点口径优化）的 Ω 挤在少数几个时段，
新口径下 Tmax = 10.46 h；10-21 版 100 星方案是 4 个轨道面的 Walker，Tmax = 4.91 h；
而 Walker 14 面 × 2 星（F = 3）Tmax 只有 1.46 h。

作为对照，只为长三角设计的极端构型——28 颗星都放在同一条 15 圈 / 1 天的回归轨迹上（568 km），
过境时刻在一天里均布——7 天 196 次访问、Tavg 0.84 h、Tmax 0.85 h，但全球覆盖率只有 2.5%；
即便用它自己的重访值当参考值，赛题分也只有约 60，远低于兼顾型构型（约 72），混合构型（部分星专门对准长三角）
同样不划算，所以没有纳入搜索。

### 2.4 回归轨道

若高度使卫星 D 天恰好绕 Q 圈（太阳同步时 ω_E − Ω̇ = 2π/天，条件为 u̇ = 2π·Q/(D·86400 s)），
地面轨迹每 D 天重复一次，单星在赤道上的升交点构成间距 360°/Q 的格子。让 N 颗星的轨迹在一个格距内
等分错开 360°/(QN)，只要该间距不超过幅宽，D 天内全球就会被铺满（T100 ≈ D 天）。
把一颗星的轨迹再平移整数个格距，D 天内的覆盖集合不变，只改变它扫过各处的先后；
同一轨道面内把相位改 k·360°/D，轨迹也恰好平移 k 个格距——这两类移动都"不损失覆盖"。

赛题高度范围内可用的回归周期（`designs.rgt_options`）如 73 圈/5 天（≈695 km）、89 圈/6 天（≈620 km）等。

新口径下回归构型的难点是：把 Ω 在一天里铺匀（Tmax）与 N 颗星的子位置交错（全球覆盖）、
轨迹落在长三角上（Tavg）要同时满足。我们试过固定 Ω 均布、在子位置排列与相位槽上做 2 分半钟的局部搜索：
28 星 73/5 能做到 T90 ≈ 2.2 d、T100 ≈ 4.95 d、Tavg ≈ 1.2 h，但 Tmax 降不到 2 h 以下，
综合分与 Walker 14 面 × 2 星持平或略低。

### 2.5 整体旋转

把所有星的 Ω 同时加一个角度，全部地面轨迹整体东移，全球覆盖指标不变，但各面过境长三角的
时刻与哪几圈轨迹扫过长三角都会变。28 星 Walker 14 面 × 2 星（F = 3）的 Tmax 随旋转角在 1.46–2.78 h
之间变化（Tavg 只变 3%），所以旋转角作为单独的设计变量来优化。

## 3. 评估：解析穿越法

逐步长仿真（10 s / 1 s 步长扫描 64800 个全球格点和 3957 个区域格点）对 28 星需要约 2.3 s，
不适合大规模搜索。`fasteval.py` 改用解析法：

- 纬度 φ(t) = asin(sin i · sin u(t))，u 随时间线性增长，穿过某一纬度行的 u 只有升段、降段两个值，
  对应时刻是等差数列；穿越点经度 λ = Ω + Ω̇t − GMST(t) + atan2(cos i sin u, cos u) 也是解析的；
- 在穿越点附近把地面轨迹看成直线：该行上横向距离 ≤ 地面半幅宽 d 的点，经度偏差满足
  |Δλ| ≤ d·|v| / (R·cos φ·|v_N|)（v 为地固系地面速度，v_N 为北向分量）；
- 全球：每次穿越覆盖的格点直接写入"首次覆盖时刻"；
- 长三角整体：一颗星穿过某一纬度行时，只要该行上有长三角格点落入视场，就记一次"命中"；
  格点在方形视场（沿迹半角 0.81°）内停留 ±d/v，命中区间取 [t − d/v, t + d/v]；
  同一颗星相邻命中相隔超过 300 s 切成两次访问，访问区间 = [首次命中, 末次命中]（`fasteval.sat_passes`）；
- 所有星的访问区间按开始时刻排序，间隔 = [0, 首次开始]、相邻两次 max(0, 后一次开始 − 前一次结束)、
  [末次结束, 168 h]，Tavg / Tmax 取平均 / 最大（`fasteval.region_revisit`，不合并，计分用）；
  另给合并口径（各星访问区间取并集后再取间隔）作参考；整体访问次数 < 2 时重访项判 0；
- 逐格点旧口径（`fasteval.revisit_stats`）仍保留为参考输出，不进入评分。

单次评估 28 星约 0.15 s，改一颗星只需重算这一颗（约 6 ms）。逐步长仿真（`exactsim.py`）
按 1 s 采样判定"有长三角格点落入方形视场"，用同一套切分与统计函数，二者独立实现：
10-21 版 28 星方案两边都是 146 次访问、Tavg 1.124 h、Tmax 10.46 h（合并口径 120 次、1.365 h），
Walker 14 面 × 2 星（F = 3）都是 127 次、Tavg 1.289 h、Tmax 1.459 h，差别在 0.001 h 以内（`validate.py` 第 8 项）。

## 4. 优化算法（`optimizer.py`）

目标函数直接用赛题评分公式（`score.py`）：

  J = 28·T90*/T90 + 12·T100*/T100 + 42·Tavg*/Tavg + 18·Tmax*/Tmax

其中 Tavg / Tmax 是长三角整体、不合并口径。拿不到别队的最优值，就把**本次搜索中所有评估过的构型里各指标的最优值**
当作 *（相当于假设对手都能做到我们在每一项上能做到的最好），并按赛题规则处理特殊情况：未达 90% 覆盖则全球项为 0，
未全覆盖则 T100 项为 0，长三角整体不足两次有效访问则重访项为 0。搜索时另加少量平滑辅助项
（覆盖时刻 99% 分位、平均首次覆盖时刻、重访间隔的均方根），只用来提供改进方向：
Tmax 只看一个间隔，多数单星移动不改变它，均方根让"把各间隔拉平"的移动也能被接受。

四个阶段：

1. **构型初选**：Walker（多种面数 P、相位因子 F，升交点赤经铺满 360° 或只铺 180°——后者让升段、降段的
   过境时刻交错；N 不整除时前几个面多放一颗）；每个回归周期下的回归交错构型（"成簇 / 均匀分散 / 黄金分割跳格"
   三种格子分配，以及升交点赤经在 360° / 180° 内均布的两种排布），再把得分最高的 3 个 Walker 结构放到各回归高度上。
   28 星时共 215 个构型。
2. **整体旋转**：对得分最高的 6 个构型，在 0–360° 内按 3° 粗扫、0.25° 细扫整体旋转角，
   只算区域重访（全球覆盖不变），取重访得分最高的角度。
3. **坐标下降**：对前 2 名逐颗卫星做一维穷举，只接受使 J 上升的移动，直到一整轮没有改进或用完时间预算：
   - 回归构型：轨迹平移 Q−1 种整格（过境地方时随之变）、同一轨道面内换到另外 D−1 个回归相位槽
     （Ω 与过境地方时不变）、同一条轨迹上前后移半圈以内 36 档——三类移动都不改 D 天内的全球覆盖集合；
   - 其他构型：轨迹东移量（相位不变）与面内相位（Ω 不变）各做"72 点粗网格 → 9 点细网格 ×2"的三级搜索。
4. 坐标下降的结果并入参考值，按同一组参考值取 J 最高的构型，换算成 (h, i, Ω, u) 输出。

随机性只有坐标下降的卫星顺序（固定种子）；但坐标下降按时间预算停止，不同机器、不同预算下
跑的轮数不同，结果会有小幅差别。默认时间预算 600 s，可用 `--budget` 调整。

### 4.1 全球覆盖与区域重访的权衡

新口径下两者的矛盾小了很多：长三角整体重访只要求各轨道面的过境时刻在一天里铺匀，
这与全球覆盖要求的"轨道面在经度上铺开"基本同向，所以多面 Walker 两头都好。
剩下的矛盾在回归轨道：回归轨道的 T90 / T100 更好、访问次数也略多，但子位置交错、Ω 均布与相位三者
难以同时满足，Tmax 偏大。算法不预设偏向哪一边，用赛题权重直接比较：构型族与回归周期由初选决定，
过境时刻与轨迹落位由整体旋转决定，各星相位由坐标下降决定。

### 4.2 轨道面与相位

输出不限定 Walker 形式：每颗星的 Ω、u 由轨迹平移量与时间提前量换算得到。若初选与坐标下降保留了
Walker 结构，输出就保留其轨道面分组（P 个面、每面 N/P 颗、相位因子 F）；坐标下降对 Walker 构型的
"面内相位"移动不改变 Ω，所以面的分组与各面过境地方时都保持不变，只调整哪颗星在哪天扫过长三角。

### 4.3 与伐谋的结合

程序里的"智能决策"体现在构型族的选择、整体旋转与逐星坐标下降都由评分公式驱动、自动完成。
伐谋用于在此基础上演化搜索策略本身：`evaluate.py` 把任意候选星座按同一套口径折算成赛题分
（参考值固定，最后一行输出裸分数），伐谋改写 `designs.py` 的构型族与 `optimizer.py` 的移动方式、
预算分配，以评估分为适应度迭代。新口径下值得交给伐谋演化的方向：回归轨道上"子位置排列 + 相位槽"的
成对交换移动、不同高度混合的构型族。

## 5. 与工程仿真的对应关系

- 输出为平均根数（J2000，历元 2027-01-01 00:00:00 UTCG），e = 0、ω = 0，u 为纬度幅角；
  a = 6371 km + h。STK 中用 J2Perturbation 传播器、按经典根数（a、e、i、ω、Ω、M = u）建星即可复现。
- `stk_export.py` 另外按同一模型导出每颗星 7 天 30 s 步长的 J2000 星历（.e），
  以及建场景、加矩形传感器 `Rectangular 0.81 0.81`（沿迹、交叉迹半角都是 0.81°，答疑 #46）的 Connect 命令。
  选矩形而不是 Simple Conic 0.81°：两者幅宽相同，矩形与我们的方形视场判据一致。
- 全球覆盖判据是"格点到星下点轨迹的横向距离 ≤ 地面半幅宽"（10 s 步长之间按连续推扫补齐）；
  长三角判据是"格点落在方形视场内"。长三角整体重访在 STK 里对应"各星对长三角 AreaTarget 的 Access 区间"，
  按第 3 节的切分与间隔规则统计，而不是逐格点的 Revisit Time。
