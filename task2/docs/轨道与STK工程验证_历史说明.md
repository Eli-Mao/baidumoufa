## 轨道模型与使用边界

统一历元为 2027-01-01 00:00:00 UTC，分析至 01-08；圆轨道，输入角度为度。高度相对于题目给定平均半径：

$$a=6371+h\quad(\mathrm{km}),\quad n=\sqrt{\mu/a^3},\quad p=a(1-e^2).$$

J2 使用参考半径 6378.137 km、$\mu=398600.4418\ \mathrm{km^3/s^2}$、$J_2=1.08262668\times10^{-3}$。令 $K=J_2n(R_e/p)^2$：

$$\dot\Omega=-\frac32K\cos i,\quad
\dot\omega=\frac34K(5\cos^2i-1),\quad
\dot M=n+\frac34K\sqrt{1-e^2}(3\cos^2i-1).$$

太阳同步条件为 $\dot\Omega=360/365.2422=0.985647\ldots$ 度/日，由此反解逆行轨道倾角。700 km 的倾角约为 98.1589°。圆轨道纬度幅角 $u=\omega+M$，升交点周期必须用 $2\pi/(\dot\omega+\dot M)$，不能只用 $2\pi/\dot M$。

`propagate_j2_secular` 默认速度是位置的时间导数，包含节点进动项，适合星历和几何。`velocity_mode='keplerian'` 只用于构造数值积分的瞬时圆轨道初值，不是平均根数转瞬时根数。RK4 使用二体加 J2 加速度，末步缩短到请求时刻；重复、乱序、非整步时间均可处理。

数值传播验证比较节点周期，并按数值轨道自身平均半长轴计算解析周期。历史复核的周期差为 0.008 s；这不证明相同数字的平均根数和瞬时根数能给出逐点重合的轨迹。STK J2 保留长期效应，仍须比较独立导出的轨迹并核对常数设置。[STK J2 模型说明](https://help.agi.com/STKComponentsJava/Javadoc/agi-foundation-propagators-J2Propagator.html)

惯性到地固变换采用 GMST 单轴旋转，忽略岁差、章动、极移和 UT1−UTC；不能标称为完整 J2000→ITRF。太阳向量是日期平赤道近似，β 角和地方时只作诊断，不参与精密日照验收。太阳同步不等于 β 角全年恒定。

## 几何与统计口径

相机沿迹、交叉迹半视场角均为 0.81°，对地无侧摆。球面地面半宽采用近地交点：

$$d=R\left[\arcsin\left(\frac{R+h}{R}\sin\eta\right)-\eta\right].$$

超出地平线的边缘角直接报错。`access_geometry.rectangular_access` 用视线在相机轴上的分量判断矩形视场，并显式排除地球遮挡。

全球覆盖仍由现有 `run_sim.py` 计算：切平面方形视场近似，默认 10 s 采样间作沿迹连续推扫补齐。候选格点搜索按视场包围范围扩展，以免固定邻域漏掉高纬或矩形角点。1°×1° 格心以**格点数量等权**统计首次覆盖；T90 是第 ceil(0.9N) 个首次覆盖时刻，全部命中才有 T100，不能替换为面积加权百分比。`reachable` 按设计倾角和载荷可达范围动态选择有效格点；`all` 作为全地球诊断，不能用可达区的 100% 宣称覆盖了不可达极区。

长三角由 `continuous_region.py` / `run_official_region.py` 独立计算正式边界与矩形视场的连续区域相交，**不设区域评价网格**。模型使用 6371 km 球面、外环短大圆弧边界和沿地固速度定向的对地相机；通过包含关系及边界解析交点判断空间相交，包含边界触碰。当前实现面向本次无孔洞、非跨日期变更线的区域，不能泛称支持任意 GeoJSON 拓扑。

默认以 0.125 s 扫描，对已发现的转换二分细化至 0.01 s，再以 0.0625 s 复核逐个窗口。1 s 与 0.5 s 的早期试算出现不同访问次数，不能作为收敛证据。**空间解析相交不等于时间上绝不漏访**：没有采样点落入的短暂擦边访问仍可能漏掉，细化已经发现的边界不能恢复未发现的窗口。步长减半是必要的数值证据，不是完整性证明。

每颗星访问三个区域分量的并集，形成该星访问整个长三角的连通区间；同星仅合并重叠或相接窗口，不填补正长度间断。旧代理的 300 s 切分阈值没有官方依据，连续区域计算不沿用这一规则。然后保留不同卫星的访问，按开始时间排序，依项目对“不合并”的解释统计首尾与相邻间隔；重叠间隔截为 0，另输出跨星并集的真实无覆盖间隔作为参考。少于两次整体访问判重访无效。

“不合并”具体如何处理重叠、包含和同起点访问仍是项目解释，答疑没有给出完整算法；它不等同于跨星并集的无覆盖间隔。边界触碰、时间容差也属于当前实现选择，须在 STK 逐层核对。

## 一次运行本地验证

在 `task2` 目录下、已安装 requirements.txt 的 Python 中运行：

```powershell
python engineering_run.py
```

本机可用解释器是外层新建的 `.venv-task2/Scripts/python.exe`，可运行：

```powershell
../../.venv-task2/Scripts/python.exe engineering_run.py
```

入口默认读取 `out/n28/constellation.csv` 和正式边界，写入 `out/qa55_n28/`，依次执行测试、历史代理校验、全球及区域网格诊断、连续区域计算、两类步长减半复核和 STK 导出。`grid_proxy.json`、`grid_proxy_fine.json` 的区域项仅为旧链路诊断；最终 `metrics.json` 的全球项取 5 s 复核值，区域项来自 `continuous_region_fine.json`。可用 `--region-step` 修改连续区域粗步长，复核使用其一半。

任一步失败立即退出；`step_*.log` 保存原始输出，`run_manifest.json` 记录输入、边界与源文件 SHA-256、依赖版本和执行状态。连续区域检查要求两种步长访问次数一致，逐星逐区间端点差不超过 0.02 s，Tavg/Tmax 差均不超过 1 s。代理模型另沿用自身比较门限。所有门限均是工程检查选择，**不是赛事官方容差或 STK 精度承诺**。换机器应按 requirements.txt 重建环境。

仅复核正式区域时可运行：

```powershell
python run_official_region.py --elements out/n28/constellation.csv --out out/qa55_n28/continuous_region.json --step 0.125 --tolerance 0.01
```

## STK 11.6 实机结果与复现

2026-11-05 已完成原生 J2、全球 Coverage 与连续区域访问验证。最终结果、场景包、复现命令和偏差说明见 [STK 实机验证记录](STK实机验证记录.md)，总证据为 `out/stk_validation_eop2026/validation_summary.json`。

本次固定使用 2026-11-04 更新的 EOP 预测快照，覆盖完整 2027 年仿真时段。系统安装的 2019 EOP 不含目标日期，其结果另作历史基线。有效区覆盖为 58775/59040（99.551152%），T90 为 242805.429524 s，7 天内未达到 T100。长三角整体访问 169 次，平均重访 3499.792507 s，最大重访 10027.219187 s。

全球最大自适应步长 60/30 s 的逐点结果通过收敛复核；区域 0.125/0.0625 s 因遗漏约 0.094 s 间断而未通过，最终 0.0625/0.03125 s 得到相同的 169 次访问，端点最大差约 0.007 s。细采样按卫星分组执行，核对相同完整场景、数据与无重复无遗漏工作清单后组合。所有容差属于工程选择，不是赛事官方标准。

独立轨道共 282268 条采样。默认 `first_order` 最大位置差约 1.827 km；显式采用 `rate_model='stk'` 后为 1.962980 m。新增相同约定的太阳同步倾角和高度反解，并通过独立单星 STK 节点进动率对照。28 星本次输入仍保留原构型；辅助设计试验没有混入其指标。

`stk_export.py --eop <文件>` 可将地球定向数据固定进输入包。`run_stk.ps1 -Engine` 调用原生无界面引擎，自动暂存到英文路径并复制结果回项目。推荐全球 `-GlobalAdaptive -GlobalMaxStep 30 -ParallelCores 8`、区域 `-RegionStep 0.03125`；另用 60 s 和 0.0625 s 比较。姿态必须显式 `NadirECFVel Offset 0`。

区域经原生 Access 命令设置固定采样、事件容差 0.01 s 和采样对齐 TimeBound 0.001 s，关闭光行时，并核对原生保存的 .sca。早期仅凭 COM 读回值得到的 151 次结果已排除。全球解析器严格读取 COV 6.0，转换弧度、核对点表并按点数统计。最终场景重新打开后确认 28 星、传感器、区域、覆盖定义、全部格点及冻结 EOP 均完整。

Python 球面与简化地固旋转仍与 STK 椭球及完整变换不同；旧优化器和参考值也未按新指标重新搜索。最终证据分别记录原生计算收敛、完整模型等价和构型达到全覆盖，后两项不因一次轨道对照而自动变为通过。
